Session agenda and presenter guide

The eight discussion items below use S1-S5 for live evidence. This sample does not establish a customer's current architecture, approve a pilot, or assign owners. Keep customer-specific notes outside this console.

  1. Objectives and success criteria. Agree the representative workflow, identify each identity boundary, exercise a governed read, and inspect its audit evidence. A completed response or a returned query row is not an end-to-end pass.
  2. Current-state architecture and requirements. Confirm the caller, existing runtime, APIs/systems, data, authorization, network and audit requirements. The configured domain is synthetic, not a customer's current state. The domain prompt is loading.
  3. Foundry Hosted Agents and architectural fit. Discuss managed hosting, the Responses contract and runtime/network requirements. Select either framework and use a domain prompt; the direct gateway selector does not change deployed agent routing.
  4. Agent identity, user identity and authorization. Separate deployer sign-in, console managed identity, hosted-agent instance identity and explicit console-to-APIM user OBO. OBO is user delegation, not per-record business authorization or hosted-agent delegation.
  5. APIM, MCP and downstream APIs. Discover live schemas, read the sample catalog and records, and compare native MCP with REST-as-MCP. REST and the explicit tool-denial probe are APIM-only. Writes require separate confirmation and disposable data.
  6. Traceability, monitoring and audit. Inspect query 01 for tool/identity evidence, 04 for a selected trace, and 02/11 for token sources. AI Gateway tokens are Foundry-observed, not proof of native export or token-limit enforcement. Record missing joins as gaps.
  7. Reference architecture and candidate pilot. Use the reference below to discuss one read-only-first workflow, one approved downstream interface, prerequisites, safeguards and measurable acceptance. Customer fit, pilot approval and production hardening remain to agree.
  8. Open questions, decisions, owners and next steps. Close with confirmed decisions, unresolved questions, a named owner and next review date for each item. Unconfirmed owners and dates stay to agree; this console does not save a decision or action register.
